# 登录、设备与 VPN 交互重设计

日期：2026-10-12。状态：已按本设计实现 3.4.0，服务器/目标验证与手机验收边界见 [交付说明](ui-3.4.0.md)。以下保留设计时的现状分析。

## 1. 目标与不可破坏的规则

- 点击登录只发起官方浏览器认证，绝不启动 VPN 扩展、请求 VPN 授权或创建网卡。
- 系统 VPN 授权只能由用户明确点击开启 VPN 触发。拒绝或取消不注销账号。
- 账号认证、设备信息刷新、系统 VPN 网卡和对端通路是独立状态。
- 页面能看见设备，不代表本机 VPN 已开启；无在线设备也不妨碍开启 VPN。
- 保存的显示信息不作为登录有效或允许挂接网卡的证明。
- 接受“开启”的操作与真正建立网卡分开：用户能发起操作，内部仍验证有效账号、地址和系统资源。
- 正常关闭 VPN 不退出登录；查看页面、刷新设备不影响已建立的 VPN。
- 等待必须有真实阶段、明确原因、取消/重试出口，禁止无限灰开关、无限全页遮罩。
- 保留官方核心、一个状态写入者、原有设备身份与 Tailnet IP；不升级 Go/Tailscale。

## 2. 当前逻辑与问题

| 当前行为 | 实际调用/条件 | 问题 |
| --- | --- | --- |
| 登录先申请 VPN 授权 | ClientController.login → ensureService → PlatformNetworkClient.start → startVpnExtensionAbility → tailscale.login | VPN 扩展被当成账号服务，授权时机错误 |
| 保存账号启动也先恢复扩展 | restoreSession → ensureService | 浏览账号与设备依赖 VPN 生命周期；可能无操作就弹授权 |
| 开关灰掉 | busy/vpnChanging，或缺 networkMapReady+IPv4、Running | 把可发起操作与已完成准备混为一谈，没有明确禁用原因 |
| 首页一直“核对连接并同步设备” | 非 Running 且无 networkMapReady 的固定文案 | 不代表真的在核对/同步；账号、配置、通路混用 |
| 刷新可能锁住开关 | 手动 refreshData 设置全局 busy；查询与操作复用串行原生锁 | 设备刷新成为操作前置条件，甚至诊断也等待 refreshTask |
| 开关亮起但未连接 | isOn = vpnWanted 或 vpnRunning | 开启意图、恢复中、实际连接混在一起 |
| 网络异常像登录异常 | 通用错误和后台恢复状态集中在同一 message | 无法区分重试连接、重新认证、系统授权或设备刷新失败 |

这些是当前实现的行为，不是设计应当保留的限制。上一轮仅调整遮罩和 Starting 条件，没有解决根本耦合。

## 3. 用户流程

### 首次安装 / 卸载后重装

1. 打开：直接显示欢迎页，不请求 VPN 授权，不恢复任何旧开启意图。
2. 点“登录 Tailscale”：按钮局部显示“正在打开登录页面…”，后台前台核心获取官方一次性认证链接。
3. 打开系统浏览器。获取链接失败时原地显示原因和“重试”，不弹 VPN 授权。
4. 返回 APP：显示“正在确认登录结果…”，仅登录区域局部等待，可重新打开登录页面/检查结果。
5. 收到可信账号认证成功状态后进入首页；不等待 Running、DERP、设备列表或 VPN 网卡。
6. 首页明确“VPN 未开启”；设备列表独立加载。
7. 用户点击开启 VPN，才触发系统 VPN 授权；允许后开始建立连接。
8. 网卡、保护和挂接确认成功才显示“VPN 已开启”。对端能否直连/中继另行表示。

浏览器关闭、认证未完成、网络断开不是登录成功，也不应反复自动打开浏览器。重复登录点击不产生多个认证任务。

### 已登录再次打开 / 覆盖安装

- 先显示账号和已有设备信息；历史信息标注“上次同步”和时间。
- 有健康的后台核心时只连接它，不重新申请授权、不重建核心。
- 后台核心不存在且 VPN 原本关闭时，在前台恢复账号/设备查询，不启动 VPN 扩展。
- 临时断网不切回欢迎页、不清账号；明确凭据失效才显示“登录已过期，请重新登录”。
- VPN 已开启时继续显示实际状态，查询失败不将已验证的网卡误判为关闭。
- 曾明确开启且允许自动恢复时可复用现有授权恢复；如系统要求重新授权，停止自动弹框，显示“需重新授权”，由用户点击连接触发。
- 覆盖安装保留身份、账号与原有用户意图；干净安装没有历史开启意图。

### 开启 / 关闭 VPN

开启操作：用户点击 → 必要时系统授权 → 准备有效本机配置 → 创建/保护/挂接网卡 → 实际开启。

- 已登录或保存会话待核对时，可点击开启；核对在这次操作内进行，而不是长期灰掉。
- 等待期间提供“取消连接”。不把尚未建立的网卡呈现为“已开启”。
- 已知未登录显示登录入口；已知需要管理员批准显示批准说明与检查入口，不假装可连接。
- 授权拒绝/取消：回到关闭状态，保留账号，下一次用户点击可以重试。
- 配置仍未获得、无物理网络、被其他 VPN 占用：就地显示具体原因，不等待设备列表。
- 开启失败或超时：停止本次请求和盲目重试，显示“连接失败”与“重试”；晚到的结果必须清理，不能超时后偷偷开启。
- 点击关闭立即撤销开启/恢复意图，再完成网卡清理；仅网卡清理阶段显示“正在关闭”。
- 关闭成功保留账号与设备；暖态 ON/OFF 继续使用同一后台核心。
- 未确认清理完成显示“关闭待确认”，保留重试关闭入口，不能谎报关闭成功。

### 设备列表

- 登录成功即可后台刷新；不等待用户开启 VPN。
- 刷新只占用列表局部状态，不占全局 busy，不阻塞开启、关闭、设置或诊断。
- 区分“正在更新”“当前没有在线设备”“离线/同步失败，显示上次结果”。
- “在线”只来自当前已获取的控制面数据，不表述为本机已连通；缓存显示“上次记录”。
- 新增真实异常与上次更新时间；取消筛选、刷新和切页面不重启核心。
- API 调用应有原生超时和取消，不仅用 JS Promise 超时隐藏仍占锁的查询。

### 退出登录

- 设置中主动点“退出登录”，确认后先取消恢复/待完成开启，再关闭 VPN，最后执行官方注销并清理账号/设备显示缓存。
- 普通关闭 VPN、系统回收、网络中断不能执行注销。
- 关闭/注销失败如实显示并可重试，不提前画出“已退出”。

## 4. 页面、按钮与状态

内部独立维护：

- 账号：未登录 / 正在登录 / 待确认 / 已登录 / 需重新登录 / 待管理员批准。
- 设备：未加载 / 更新中 / 当前列表 / 历史列表 / 更新失败。
- VPN：关闭 / 等待授权 / 准备配置 / 建立中 / 开启 / 恢复中 / 失败 / 关闭中 / 关闭待确认。
- 通路：待建立 / 直连 / 中继 / 异常；没有实际观测就不声称可达。
- 用户意图：希望关闭/希望开启，不能直接充当已连接状态。

| 用户看到的状态 | 主操作 | 其他操作 |
| --- | --- | --- |
| 未登录 | 登录 Tailscale | 设置可用；没有 VPN 授权 |
| 浏览器认证中 | 检查登录结果 / 返回登录页面 | 可取消；不全页锁死 |
| 已登录，VPN 关闭，设备更新中 | 开启 VPN | 列表局部刷新；其他页面可用 |
| 已保存会话，暂时离线 | 开启 VPN（点击后报告原因） | 浏览历史设备、重试同步 |
| 等待授权 / 配置 / 建立中 | 取消连接 | 不显示已连接；列表与设置可用 |
| VPN 开启 | 关闭 VPN | 设备可独立刷新 |
| 连接失败 / 授权拒绝 | 重试连接 | 账号保留；显示明确原因 |
| 原连接意外丢失 | 取消恢复 / 关闭 | 显示恢复阶段；不弹新权限框 |
| 已知登录失效 | 重新登录 | OFF/取消仍可用；不能继续建立新网卡 |
| 关闭待确认 | 重试关闭 | 诊断与系统设置入口可用 |

采用现有开关布局时：开关只在实际网卡确认后呈开启态，建立中显示局部进度和独立取消按钮；不能因为设备刷新灰掉。等待用户系统授权时不占用整个页面。设置内的诊断状态和日志读取不能等待设备刷新任务。

## 5. 等待、错误与恢复

- 不设远端同步/认证/DERP驱动的全页遮罩。页面布局和本地显示缓存先渲染。
- 本地初始化确有关键操作时仅局部标识；可浏览页面、查看失败原因或重试。
- 获取登录链接设置有界原生请求，建议 15 秒；失败不触发 VPN 授权。
- 登录观察超过当前两分钟窗口：提示“尚未确认认证完成”，提供继续检查，不声称凭据失效。
- 系统授权等待不计入连接建立计时；用户确认后，配置/建立设置明确的总截止时间，建议 30 秒。超时结束本次手动连接，不把未取消的原生任务留在后台。
- OFF/取消不排队等待慢设备查询。状态查询可并行读快照，资源变更仍串行。
- 意外丢失已经开启的连接可后台重试；无物理网络等待网络恢复，已知认证/授权拒绝/其他 VPN 则暂停。
- 不能声称 API24 能区分系统设置手动 OFF 和系统回收；未能辨识的停止不盲目抢占，给出重新连接入口。自动恢复恢复哪些停止事件需要后续设备证据。
- 全应用被终止时无法靠应用自身定时器运行；重新打开按实际状态恢复，不能误报一直在线。

## 6. 必要架构调整（不是挪弹框）

当前所有产品核心都运行在 VPN 扩展中，启动扩展就可能触发系统授权。仅删 ensureService 会使 login 没有核心，不能解决问题。

选定方向：**VPN 未授权时，官方核心可由前台宿主运行；VPN 首次开启时，转交给已授权的扩展宿主。任何时刻仍只有一个凭据/核心写入者。**

1. 将核心生命周期拆为显式账号会话宿主与 VPN 扩展宿主，账号路径不调用任何 VPN SDK。优先复用当前 wgengine/ipnlocal 与 detached logical TUN，不重新引入模糊的 tsnet 自动 fallback。
2. 前台宿主只负责官方认证、配置和设备同步，不创建系统网卡，不添加系统路由，按前台生命周期维护网络监听。后台被暂停时不承诺继续登录确认。
3. 已有健康扩展宿主时，前台作为客户端复用，绝不再启动第二个前台核心。
4. 首次开启需要授权时使用两阶段转交：扩展启动获授权后先等待转交，不抢写凭据；前台确认关闭并释放状态锁后，扩展才启动官方核心并读同一状态。
5. 用户拒绝授权时前台仍可查询账号/设备；等待或取消的扩展准备不能提前创建网卡。
6. 以 owner/generation/requestId 约束转交，旧快照与晚到授权不能授权新网卡；关闭不确定则停止转交，不能两个核心并发写状态。
7. 转交沿用同一个 tailscaled.state、profile、machine/node key、hostname，验证 NodeID/IP 不变。跨进程不能迁移活 Go 对象，允许一次进程核心启动，但不得成为一次重新登录或新增设备。
8. 转交失败后，只有确认扩展未持锁且无残留网卡，才恢复前台核心；否则如实报告并提供取消/诊断。
9. 正常 ON/OFF 不重复转交、不重复登录，保持当前 detachable-TUN 后台核心。OFF 后扩展仍健康就复用；扩展已终止且没有开启意图时可回到前台宿主，不自动申请 VPN 授权。
10. 恢复发现需重新授权时不得自行打开授权框；移交给用户明确连接操作。

这修订了原项目“所有账号操作必须由扩展拥有”的架构规则；前台官方核心、两阶段授权转交和同身份恢复已实现。普通手机不依赖企业/PC AppServiceExtension 特权。系统弹框、进程生命周期和取消时序仍须手机验收。

## 7. 实施顺序与验收

先完成账号宿主和授权转交，再替换产品控制器，最后打包真机验收；不继续逐条补等待文案。

1. 干净安装点登录：只弹官方浏览器，VPN SDK start/create/protect 调用数为零。
2. 浏览器返回认证成功但核心仍 Starting/无 DERP：进入首页，VPN 明确关闭。
3. 空 Tailnet/所有设备离线：账号仍可登录，配置有效可开启网卡。
4. 设备查询挂起/失败：开启、关闭和诊断不等待它，不无限 busy。
5. 首次开启：才弹系统授权；拒绝后账号、列表保留，可再次尝试。
6. 授权成功但配置等待：显示具体阶段，可取消；取消后晚到结果不创建网卡。
7. 建立失败/超时：关闭态和重试入口；没有未经用户理解的无限自动开启。
8. 两阶段转交：官方控制端只看到原 NodeID/设备；机器密钥、IP、状态锁保持正确，没有双写。
9. 转交中的关页、系统弹框晚完成、原生关闭失败、扩展退出、状态文件损坏：不双启、不误报、不泄露凭据。
10. 同一暖态 coreId 下多次 ON/OFF：OFF 无 Tailnet 系统流量，ON 正常；不重新认证。
11. VPN OFF 后重开页面/APP：没有新的授权框；账号与列表后台更新。
12. 已建立 VPN 时控制面失联：不单凭查询失败拆网卡；通路/账号状态如实显示。
13. 明确退出登录：先停止 VPN/恢复，再注销；重启不自动恢复登录或 VPN。
14. 覆盖安装保留身份；卸载后重装不恢复旧开启意图。
15. 自动恢复遇到权限重新确认或其他 VPN：暂停等待用户，不后台反复弹框或争抢。

实现后运行完整 make check、签名/验签；必须另做真实手机的浏览器、系统授权、转交身份、冷启动、ON/OFF、Moonlight 和取消时序验收。测试替身不能证明系统弹框触发时机。
