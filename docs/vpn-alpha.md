# VPN Alpha 范围与资源契约

当前开发目标：**0.1.0-alpha.1**，见 [版本规范](versioning.md)。完整状态所有权见
[架构](architecture.md)，实际手机验收见 [设备指南](device-test.md)。

## 支持范围

- 官方浏览器登录、官方控制平面与 WireGuard/DERP 引擎，不替换上游协议或 ACL。
- 系统接口配置节点 IPv4 `/32`、MTU 1280 与 `100.64.0.0/10` Tailnet 路由。
- IPv4 TCP/UDP 和有限的 ACL 过滤本地 ICMP 应答；其他应用使用 peer IP 访问。
- 不添加默认路由，不覆盖系统 DNS；MagicDNS、IPv6、出口节点、子网路由及
  always-on 不在当前承诺内。
- 固定 CGNAT 路由可能与运营商/LAN 地址冲突；真实网络的普通访问也要验收。

## 启动、关闭与身份

登录和恢复使用免系统 VPN 授权的前台账号宿主；已有健康扩展则直接复用。
显式 ON 才启动缺失扩展，并在系统要求时请求授权。前台/扩展通过绑定 owner
和意图 revision 的两阶段握手转交同一持久状态；不能同时打开两个核心。
用户取消、拒绝或 OFF 必须阻止迟到的操作偷偷挂接网卡。

保护扩展物理网络传输后再挂接接口，避免 VPN 流量递归进入自身。
正常 OFF 分离 TUN、等待包 I/O 结束并销毁本次平台接口，**保留健康核心、
控制连接与账号状态 lease**；不 Logout，也不每次重启扩展。暖态 OFF 不是零
后台资源模式。退出账号/明确服务关闭与正常 OFF 是不同操作。

Go 只持有带 CLOEXEC 的重复 FD；ArkTS 拥有原始描述符并负责平台清理。
未确认 detach/close/destroy 完成时保持可见错误，不凭一个 disconnected 字段
报告资源已清理。登录、已认证、接口连接、peer 业务流量四者不是同一事实。

## 平台限制与证据

HarmonyOS 可以暂停/终止应用或扩展。当前 app-runtime 恢复与轮询不是系统
保活，不保证杀进程/重启后自动恢复；缺失宿主不应偷偷弹出后台授权。

宿主回归包含实际官方引擎的加密包、C ABI/NAPI 和生产状态机；目标构建
包含真实 ARM64/ArkTS 编译。两者均不能代替真实系统授权、ArkUI 渲染、
直连/DERP 业务流量、锁屏和切网验收。当前预发布的这些手机用例尚待完成。

[历史报告](archive/vpn-alpha-3.2.0.md)；其中 OFF/核心替换行为不再代表当前版本。
