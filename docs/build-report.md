library. It does not provide ArkTS UI, VPN Extension integration, login, or a
working network connection.

## Device status

Not tested. A successful build must not be interpreted as proof that the
library loads or that networking works on a HarmonyOS device.

In particular, real-device validation still needs to cover the HarmonyOS
dynamic loader, application sandbox storage, socket behavior, network change
monitoring, DNS integration, background execution, and VPN Extension wiring.

## Phase 1 handoff (completed in Phase 2)

1. Package the shared library and generated header into a minimal Native C++
   HarmonyOS module.
2. Load the library on an ARM64 device and call only the version and core probe
   functions first.
3. Add lifecycle and status C ABI functions around `tsnet.Server` without
   exposing Go pointers across the ABI.
4. Integrate platform-owned networking and VPN Extension plumbing before
   attempting login or persistent tailnet connectivity.

## Phase 2 build status

The minimal Stage-model HAP now compiles and packages successfully with the
HarmonyOS API 26 SDK / Hvigor 6.26.8. It targets API 26 while declaring
`compatibleSdkVersion: 6.1.1(24)` for the API 24 test device.

- ArkTS calls the native module `libtailscale_napi.so`.
- Native declarations live under `cpp/types/libtailscale_napi/index.d.ts` and
  contain named function declarations. ArkTS uses HarmonyOS's Native-module
  default import adaptation; declaring a normal ES `export default` produced
  `undefined`, while direct named imports caused an API 24 `SyntaxError`.
- The NAPI bridge records `libtailscale_ohos.so` as a basename-only
  `DT_NEEDED` dependency and contains no build-time RPATH/RUNPATH. Earlier HAPs
  embedded `/workspace/.../libtailscale_ohos.so`, which prevented the device
  loader from recognizing the NAPI module and surfaced as an undefined ArkTS
  import.
- Potentially blocking Go operations run through `napi_create_async_work` and
  never execute on the ArkUI thread.
- `tsnet.Server` receives the explicit app-private state directory and UI
  hostname; no auth key is compiled into the application.
- Go errors and recovered panic stacks are returned as JSON and retained in a
  bounded log buffer; NAPI forwards the buffer to HiLog using tag
  `TailscaleNAPI`.
- Diagnostics cover private storage read/write, TCP/UDP socket creation, DNS,
  interface enumeration, Tailscale network-monitor initialization, and default
  route discovery.
- The packaged HAP contains `libtailscale_napi.so`, `libtailscale_ohos.so`,
  `libc++_shared.so`, and `ets/modules.abc`.

### Phase 2 real-device results

Version 2.0.3 was installed on a HarmonyOS 6.1.1/API 24 device. Real UI output
and HiLog proved `abiVersion: 2`, Tailscale 1.86.2, Go 1.24.5,
`coreProbe: true`, and a successful transition to `state: started`. HiLog also
proved UDP4/UDP6 Magicsock creation, WireGuard device Up, DERP receive routines,
engine creation, and persistent state at the app-private
`filesDir/tailscale/tailscaled.state` path.

Storage, TCP, UDP, DNS, interface enumeration, and the Tailscale network monitor
passed. HarmonyOS denied raw default-route Netlink bind and RTMGRP subscription,
so Tailscale fell back to polling with an empty default-route interface. Forced
UDP buffer enlargement was also denied and explicitly reported as a
throughput-only limitation. The fake/no-op TUN, router, and DNS implementations
are expected for `tsnet`; full-device routing remains a VPN Extension task.

### Phase 3 build status

Version 3.0.6 / C ABI 3 adds async LocalAPI status, official interactive login,
logout, and visible online-peer listing. Filters support all peers, ACL tags,
user identity, and hostname text. ACL `group:` membership is deliberately not
claimed because it requires the Tailscale management API and a server-side OAuth
credential. Authentication URLs are opened by ArkTS with `UIAbilityContext.openLink`
and redacted from Go/HiLog output. Login URL acquisition uses the same IPN Bus
`BrowseToURL` event as the official Tailscale CLI, and platform diagnostics
include an HTTPS reachability check for the official control plane.
The UI also provides an independent browser-launch test and falls back from
`openLink` to an implicit `ACTION_VIEW_DATA` Want when necessary.
The HiLog bridge forwards one atomic 2.4 KB newest-tail record instead of
hundreds of individual historical lines or multiple chunks, avoiding HarmonyOS
log-rate limiting that hid the newest control/login failure.
Version 3.0.5 additionally sanitizes embedded NUL bytes before logs cross the C
ABI; the repeated device-side truncation at `[v` was therefore not mistaken for
a HiLog limit. Failed login results also embed the newest 24 sanitized Go log
lines in `debugLogs`, allowing the next device run to report the backend failure
without relying on HDC/HiLog delivery.
Version 3.0.6 disables Tailscale's Linux `netns` socket control from the
OpenHarmony wrapper. The OpenHarmony Go fork selects `netns_linux.go`, while
HarmonyOS denies default-route Netlink access; the Linux fallback can therefore
bind control-plane sockets to `lo`. This adapter matches the official
`tailscaled --tun=userspace-networking` behavior and leaves outbound control,
log, and DERP sockets on the platform's normal network path. A host unit test
asserts that the resulting `netns.Listener` has no socket-control hook.

Go unit tests, OpenHarmony ARM64 build, Native C++ link, ArkTS compilation, HAP
payload verification, HAP signing, and native code-sign verification pass. The
user subsequently confirmed successful official authentication and online peers
on the real HarmonyOS phone with 3.0.6. This does not establish system VPN/TUN
functionality.
